# 深海投放校正台

本地 CTD cast 校正工作台：对固定 fixture 完成船上、下行、底部停留、上行分段，审阅温度与电导率延时、泵状态、传感器断点和电导率传感器热质量修正。页面使用 Canvas 在时间轴和压力轴展示原始/修正通道，并把上下行共同压力层的差异作为方案比较指标。

## 安装与演示

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm test -- --run
corepack pnpm dev --host 127.0.0.1 --port 5565
```

打开 <http://127.0.0.1:5565>，页面标题为“深海投放校正台”。

生产构建：

```bash
corepack pnpm build
```

独立 Node/Express 服务入口是 `src/server/main.ts`，Vite 开发模式通过 `vite.config.ts` 挂载同一组 `/api` 路由。

## 技术栈

- TypeScript + Node.js
- Express 本地 API
- Node `node:sqlite` / SQLite 持久化，数据库文件默认在 `data/ctd.sqlite`
- Vite + 原生 Canvas 操作页面
- Vitest 自动化测试

没有使用原生 SQLite 模块，因此安装阶段不需要针对本机重新编译 node-gyp 依赖。

## 固定 fixture 口径

固定数据由 `src/core/fixture.ts` 确定性生成，cast 编号固定为 `CTD-FIX-001`：

- 1 Hz 标称采样，0–269 秒，实际 258 条样本。
- 30–119 秒为下行，120–191 秒附近为底部停留，192–238 秒为上行，其余为船上。
- 12–29 秒包含船上注水/泵状态。
- 134–146 秒泵关闭；147 秒重启后重新形成连续段。
- 95–100 秒和 205–210 秒没有样本记录，表示采集断点；101 秒和 211 秒标记坏帧。
- 81 秒和 191 秒有人为压力回摆，用于证明压力并非全程单调，不能全局按压力排序后丢失上下行身份。
- 温度传感器合成延迟为 4 秒，电导率传感器合成延迟为 3 秒，并加入一阶电导率热质量伪影。

压力轴绘制时按相位过滤路径：下行和上行分别画线，不连接底部停留，也不把整个 cast 重新排序。

## 分段与边界

分段逻辑在 `src/core/segmentation.ts`：

- 样本先按时间排序并保留时间索引。
- 使用压力阈值、最大压力邻域和持续减压方向识别四个 in-water 段。
- 分段边界采用左闭右开：`[startIndex, endIndex)`。
- 边界右侧的第一条样本属于下一段；例如默认 fixture 的 30 秒属于下行，29 秒属于船上。
- 压力局部回摆不会改变已经由时间方向建立的上下行身份。

## 延时、泵和断点保护

校正逻辑在 `src/core/correction.ts`。有效连续段要求：

- 样本位于用户选择的注水段 `[waterStartSec, waterEndSec)`；
- 泵处于启动状态；
- 传感器帧有效；
- 相邻有效样本时间差不超过 1.5 秒。

延时对齐时只在同一个有效连续段内线性插值。泵关闭、坏帧、缺失样本导致的时间断点都会切断连续段；算法不会跨过缺口取两侧样本插值。连续段起点或终点附近若无法在本段内取得完整左右支架，输出 `alignment_guard`，不做外推。

用户可以：

- 调整当前选中的温度或电导率传感器延时；
- 调整注水段开始/结束秒；
- 勾选是否排除泵未启动样本；
- 调整热质量 `alpha`、`tau` 和增益用于审阅。

无论页面是否选择“排除泵未启动样本”，延时插值和热质量递推都不会跨过泵停或采集断点。

## 热质量和盐度

盐度使用 PSS-78 Practical Salinity 公式，代码在 `src/core/salinity.ts`。热质量处理先在有效段内对齐温度和电导率，再对对齐温度做一阶低通滤波：

- 温度滤波：`Tf += (Ts - Tf) * (1 - exp(-dt / tau))`
- 电导率热项：`alpha * beta * gain * dTf/dt`，其中 `beta = 8`
- 修正电导率：`Cs - thermalCorrection`

每个样本保留原始温度、原始电导率、原始盐度、对齐温度、对齐电导率、滤波温度、热项和修正电导率。若修正后盐度非物理（非有限、越界或修正电导率不大于 0），`salinityPsu` 置空、状态置为 `nonphysical_salinity`，诊断中保留全部中间量和被拒绝盐度。

## 上下行共同压力层

比较层使用 100 dbar bin，bin 为左闭右开：`[bin, bin + 100)`。每层分别聚合下行和上行样本，不把两个方向合并排序。表中保留：

- bin 中值压力；
- 下行、上行样本数；
- 下行平均盐度、上行平均盐度；
- `up - down` 和绝对差；
- 共同层数、平均绝对差与 RMSE。

最浅 100 dbar 冷启动层在表格中可见，但不计入稳态共同层指标，避免连续段冷启动边缘与真实传感器恢复误差混淆。

## SQLite 与运行记录

表结构在 `src/server/db.ts`：

- `casts`：cast 元数据；
- `samples`：固定 fixture 原始样本与泵/传感器标志；
- `scenarios`：方案参数、生成顺序、原始通道摘要、有效连续段数、比较指标；
- `run_logs`：导入、重置、方案生成等操作记录。

页面的“清空并重导入 fixture”调用 `/api/reset`，删除所有业务表数据后重新确定性导入。导入后可重新调整参数、保存方案并核对生成顺序。运行记录通过“导出运行记录”或 `/api/logs/export` 导出 JSON。

常用 API：

- `GET /api/cast`：原始样本与分段；
- `POST /api/preview`：只预览，不写方案；
- `POST /api/scenarios`：保存方案并递增 `generation_order`；
- `GET /api/scenarios`：按生成顺序列出方案；
- `POST /api/reset`：清空并重导入固定 fixture；
- `GET /api/logs/export`：导出 JSON 操作记录。

## 复核方式

1. 执行清空重导入。
2. 保持默认温度延迟 4 秒、电导率延迟 3 秒，查看共同层 MAD/RMSE。
3. 将延迟改为 0 且热增益改为 0，查看假性盐度尖峰和上下行差异扩大。
4. 查看 95–101、134–147、205–211 秒附近的样本，确认连续段被切断且无跨缺口插值。
5. 切换压力轴，确认下行和上行仍为两条带身份的路径。
6. 使用极端热增益制造非物理盐度，确认图上诊断点和样本提示保留中间量。
